# LOGO ASSET PACK — EYG TIRE & AUTO CARE

Version 1.0 · October 2026

> ## ⚠️ READ THIS FIRST — PROVENANCE
>
>
> **The only original file supplied by the owner is `brand/raw/eyg-profile.jpg`
> — a 720 × 720 JPEG of a 3D-rendered logo.** It is a raster. It is not a vector.
> It is not an AI/EPS/PDF master. It has no layers, no outlined type, and no
> colour separations.
>
> **Every SVG in `public/brand/` is a faithful geometric REBUILD** — the
> letterforms, the wheel, the rim, the hub, the tread arc and the speed stripe
> were all re-authored as real `<path>` geometry, measured from the raster, to
> match the original's proportions, weights, spacing, colours and optical
> behaviour. They are original artwork in the sense that they were drawn for
> this project, but they are **not** the owner's original vector artwork.
>
> **The owner must supply the true vector original (AI, EPS, PDF or outlined
> SVG) for final print use.** Until then, use these rebuilds for digital and
> for short-run print, and treat the rebuilds as provisional for anything that
> is permanent, engraved, embroidered, moulded, or applied at large scale.

## 2. Construction spec

The rebuild was drawn in the **source pixel grid of the 720 × 720 profile
picture**, so every measurement below maps 1 : 1 back to the original.

### 2.1 Wordmark — `EYG TIRE`

| Property | Value |
| --- | --- |
| Cap height | **68 units** (the "E" defines it) |
| Total lockup width | **489 units** → **7.19 : 1** width-to-cap |
| Italic shear | **13°**, applied as `skewX(-13)` so the cap line leans right |
| Baseline | `y = 354` |
| Horizontal scale | `0.682` · Vertical scale `0.680` (uniform, undistorted) |
| Stem weight | **27 units** (0.397 × cap) — ultra-bold |
| Bar weights | Top and bottom **26**, middle arm **22** (deliberately thinner) |
| Letter tracking | **5 units** (0.05 em) |
| Word space | **26 units** between `EYG` and `TIRE` |
| Letter advances (100-unit cap frame) | `E 92 · Y 106 · G 111 · T 92 · I 28 (adv 34) · R 111` |

The wordmark is drawn on **one baseline**. The original 3D render shows a
~0.4° perspective rise across the lockup (the right-hand cap line sits ~6 units
higher than the left); a flat vector lockup must not reproduce that — it is a
render artefact, not design intent.

### 2.2 Subline — `& AUTO CARE`

| Property | Value |
| --- | --- |
| Cap height | **30 units** (44 % of the wordmark cap) |
| Total width | **372 units** → **12.4 : 1** |
| Baseline | `y = 395` · Cap line `y = 365` |
| Letter tracking | **14 units** (0.14 em) · Word space **41 units** |
| Stem weight | **21 units** |
| Position | Left edge `x = 245`, right edge `x = 617` |

Right-aligned to sit just inside the wordmark's right edge (`x = 639`).

### 2.3 The wheel

| Property | Value |
| --- | --- |
| Centre | `(85, 317.5)` |
| Rotation | **+11.4°** clockwise (the top of the ellipse leans right) |
| Tyre outline | Ellipse `rx 27.8 · ry 50.2`, stroked **2.6**, round caps |
| Rim ring | Ellipse `rx 18 · ry 36` (outer 22 × 40), stroked **8** |
| Hub | 5 arms, drawn as a unit-circle star and mapped to `scale(13, 30)` — i.e. onto the rim's inner ellipse, so the spokes inherit the wheel's eccentricity |
| Bore | Ellipse `rx 3.6 · ry 6.4`, cut in the background colour |
| Lug holes | 5 ellipses `rx 1.8 · ry 2.8` at 36° offset from each arm, radius 52 % |
| Tread arc | 11 wedges, angles −110° → +52° (≈11 o'clock to 4 o'clock), inner scale 1.05, outer scale 1.13 → 1.28, angular width 4.4° → 8.8° |

| Colour | Hex | Token | Where |

| **Eylan yellow** | `#FCC605` | `--color-brand-500` | Subline, speed stripe, rim ring, hub, favicon ground accent |
| **White** | `#FFFFFF` | — | `EYG TIRE` wordmark, tyre outline, tread arc |
| **Ink** | `#06060A` | `--color-ink-950` | The lockup's negative space; the `EYG TIRE` colour on the light variant |

**Measured note:** in the supplied JPEG the logo's backdrop reads as
`#2A2720` (69.5 % of pixels) — a warm lifted near-black caused by the 3D
render's ambient light plus JPEG chroma subsampling. **The brand backdrop is
`#06060A`**, matching `--color-ink-950`, and that is what the rebuilds use. Do
not sample the JPG for colour; sample the token.

## 4. Known deliberate deviations from the raster original

These are choices, not oversights. Each is listed with its reason.

| # | Deviation | Reason |
| --- | --- | --- |
| 1 | **No 3D.** The raster is a rendered mark with soft bevels, subtle inner glow on the yellow and anti-aliased edge lighting. The rebuild is flat. | A bevel is a lighting accident, not an identity. Flat artwork reproduces correctly on a phone screen, in print, in vinyl, in embroidery and in a favicon; a fake bevel does not. |
| 2 | **The tread arc is white**, matching the tyre outline, not yellow. | In the raster the tread wedges read as specular highlights on the tyre carcass. Tying them to the outline colour makes the "spinning wheel" device read as one shape. |
| 3 | **The lockup sits on one baseline.** The raster rises ~0.4° left-to-right. | Render perspective, not design. A vector lockup must be level. |
| 4 | **The lug holes are omitted from the mono files.** | At ≤32 mm the five small ellipses fill in and turn the hub into a blob. |
| 5 | **The favicon is simplified**: the elliptical wheel and the tread arc are replaced with a circular rim + 5-spoke hub on an ink tile. | At 16 px the elliptical wheel's tread arc collapses into mush and the mark stops reading. The simplified tile is a designed small-size variant, not a scaled-down lockup. |
| 6 | **The original raster's background is not reproduced.** | The artwork files have transparent backgrounds. The JPG has a baked black field with lifted JPEG blacks and will show a visible dark rectangle on any light surface. |
| 7 | **The `&` is a reconstructed geometric ampersand.** | The original's ampersand is a bespoke 3D form. The rebuild is a clean geometric ampersand on the same optical weight and baseline as the rest of the subline. |
| 8 | **Letterforms are the closest geometric match available without the original curves**, not traced outlines. | See the banner at the top of this file. |

### 5.1 Delivery checklist for print

1. Open the SVG in **Adobe Illustrator**, **Affinity Designer** or **Inkscape**.
2. Confirm there are **no `<text>` elements** — there are none in this pack; all

   type is outlines.

3. Confirm **no embedded raster** — there is none.
4. Check the spot-colour build: `FYG Yellow 116 C` / `0 M / 0 Y / 0 K` is the

   closest stock equivalent to `#FCC605` — **verify against a physical swatch**
   before committing a print run. See [COLOR.md §4](./COLOR.md).

5. Set the document's colour mode to **CMYK** and convert with an FOGRA39 or

   GRACoL profile appropriate to the printer.

6. Convert text to objects anyway if your workflow requires it (nothing to

   convert here — but the step confirms the file).

7. Supply **PDF/X-4** (or PDF/X-1a if the printer insists) with all fonts

   embedded or, preferably, all type already outlined.

8. Add a `2x` clear-space margin around the artwork on the page.

## Acceptance checks

- [ ] Every SVG has a `viewBox`.
- [ ] No `<text>` element in any SVG.
- [ ] No `<image>` element / embedded raster in any SVG.
- [ ] Every `fill`/`stroke` is an explicit literal hex from the brand set
      (`#FCC605`, `#06060A`, `#FFFFFF`).

- [ ] Every SVG is under 20 KB.
- [ ] `logo-og.png` is 1200 × 630 and non-zero.
- [ ] `apple-touch-icon.png` is 180 × 180 and non-zero.
- [ ] `src/app/icon.svg` is byte-identical to `public/brand/favicon.svg`.

**If you need `sharp` and it is not installed**, run `npm install` (it is
already in `devDependencies` — nothing needs to be added to `package.json`).
If you must install it ad-hoc without touching `package.json`:

```bash
npm install --no-save sharp
```
